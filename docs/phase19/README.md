# Prompt 19 finance implementation

The owner routes `/owner/finance/expenses`, `/owner/finance/advances`, and `/owner/reports` now read business-scoped MongoDB records. Expenses support create, edit, and void with an audit event; void retains the original entry. Money is stored in integer paise. Related vehicle, booking, and school run IDs are checked within the owner's business.

Booking balances separate quoted fare, verified advance, verified final collection, pending claims, refunds, and outstanding. School reports carry prior months forward from immutable charges and adjustments. Split-payment refunds are allocated once across the payment's targets, and the booking and school balance helpers use the same rule. The summary distinguishes recognized school and completed-trip revenue, confirmed cash movement net of period refunds, expense cash out, outstanding, and estimated profit. Estimated profit excludes tax and costs not entered as expenses.

Reports include booking register, service revenue, collections, verification, cumulative school fees, expenses, pickup/drop events, runs and leave, driver activity, vehicle utilization, customer ledger, notifications, and audit. Lists use server pagination (20 rows) and date/search/vehicle/driver/status filters where applicable. CSV comes from owner-only API routes, applies the same filters, caps exports at 10,000 rows, and prefixes spreadsheet formula cells. Customer fee register CSV also quotes and neutralizes formula cells.

Owner-issued documents include payment receipt, school statement, quotation, booking confirmation, transport invoice, goods challan, and expense record. A verified customer can issue only their own receipt. Documents are print styled for browser Print / Save PDF. Numbers increment per business and document kind. Reissuing the same snapshot preserves its number; changed financial content issues a new numbered snapshot while retaining history. These are ordinary transport invoices and payment receipts, never tax invoices.

Verification run: `npm run build`, `npm run typecheck`, `npx vitest run apps/api/src/finance.test.ts apps/api/src/bookings.test.ts apps/api/src/fees.test.ts apps/api/src/payments.test.ts`, and `node scripts/finance-print-check.mjs`. The print check uses locally installed Chrome and checks both report and document print media, then renders an A4 PDF.

Known limits: proof is a text reference, not a file upload; no tax registration or tax invoice mode is configured. Reports show scheduled booking hours and school session counts, rather than GPS-derived vehicle distance or worked hours. The existing `/api/fees/owner` list still returns its full filtered register and its CSV is assembled from that response; the new `/api/owner/finance/reports/*` lists use server pagination. The report print button prints the current visible page; CSV exports all matching rows up to the cap.

The serial full test run on 11 November 2026 passed 82 of 84 tests. Two existing time-sensitive tests failed in `leaves.test.ts` (today leave cutoff) and `urgent.test.ts` (availability expectation). The focused finance, booking, fee, and payment run passed 19 of 19 tests. No leave or urgent behavior was changed in this phase.
