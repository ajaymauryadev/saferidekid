## Database and operational gate

The isolated database began the school flow with one `PENDING` subscription and zero children. It ended with one `ACTIVE` subscription, one child and one reserved seat. Morning event count was three including one correction; original `BOARDED` count remained one. The payment claim changed from `PENDING_VERIFICATION` with zero verified paise to `VERIFIED` with 100,000 verified paise; final booking reconciliation is above. These assertions and counts are retained in [results.json](phase09/e2e-evidence/results.json). The ephemeral database was destroyed after each run.

The index check inspected model-defined indexes on a fresh replica set. The [operations runbook](OPERATIONS_RUNBOOK.md) describes additive index migration, encrypted backup, isolated restore and financial/school reconciliation. There is **no external backup, restore drill, recovery objective or selected durable MongoDB deployment**. A production index migration must follow a backup and staging check.

The local configuration's public phone and WhatsApp fields are nonblank, but no operator confirmed their identity or tested a call. No authorized Eeco photos, UPI recipient details, real vehicle/driver documents, suitability/permits, service-category approval, parent/driver location consent or reviewed child-data retention schedule were supplied in this phase. Production vehicle photo upload is disabled until private durable storage exists; the local illustration is only a fallback. No real customer/child data or paid service was used.

For hosting selection, [Vercel says Hobby is for personal, non-commercial use](https://vercel.com/docs/plans/hobby); [Render says free web services spin down and are not for production applications](https://render.com/docs/free). [MongoDB says optional Free-cluster backups are a paid private preview with limited rollout](https://www.mongodb.com/docs/atlas/backup/cloud-backup/free-cluster-backup/), so the operator must verify availability and a restoration plan in the actual account. No commercial plan, stable HTTPS origin, alerting or provider capacity was selected or tested. The local single-origin smoke is useful evidence for compiled routing and sessions, not a deployed-service guarantee.

## Defects, fixes and outstanding severity

The initial Phase 09 browser harness failed against current Hindi defaults, proposal/counteroffer forms, consented student provisioning, guardian-confirmed leave, the revised booking wizard and phone-booking consent. Those were **stale test-harness assumptions**, not product regressions. [The Phase 09 harness](../scripts/phase09-e2e.mjs) was updated to the current contracts, then rerun successfully in both Vite and compiled single-origin modes. No production source file was changed. The original Prompt 23 harness remains available. The interrupted single-origin command completed its data run; it was rerun afterward and exited 0. No test server remains listening on the Phase 09 ports.
