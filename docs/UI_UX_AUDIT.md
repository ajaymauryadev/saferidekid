# SafeRide Kids — UI/UX audit

**16 November 2026.** Visual conclusions distinguish fresh current screenshots from historical captures. Fresh public screenshots: [home desktop](audit-current/home-1440.png), [home mobile](audit-current/home-390.png), [services mobile](audit-current/services-390.png), [login mobile](audit-current/login-390.png). The `/vehicles` and `/urgent` files in that folder show the `/services` redirect, not those intended pages. Existing `docs/phase21/` and `docs/e2e-evidence/` are earlier fixture or live-DB captures; their route reachability has changed. Fresh capture used Vite without a connected API; no private UI was visually reauthenticated. Screen observations below use current code plus those labeled older references.

## Overall visual verdict

Fresh Home, Services and Login captures at all seven target widths showed no document-level horizontal overflow. This does not establish the layout of protected pages or real-device keyboard behavior.

The blue/navy tokens, legible typography, cards, clear focusable controls and responsive public grid are a useful base. At 390 and 1440px the current public captures show no horizontal overflow. The presentation is school-only, mostly text/cards, with an illustrated van and limited mobility-brand character. The hero consumes most of the first mobile screen; booking and phone actions are absent or secondary. All observed copy is English. It does not meet the requested premium, destination-first, Hindi-friendly combined product.

## Visual evidence caveat

The fresh public screenshots were captured while the API was unavailable, so business content/vehicle listing/call links were not populated. No real student, driver, payment or location data is shown. Older HTML reference screenshots in `docs/reference/` are simulation only. A current authenticated database-backed visual pass is required after the first implementation phase; do not infer working protected controls from their source files or historical screenshots.
